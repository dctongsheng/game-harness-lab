# V1 实现说明

实现日期：2026-10-17。此文描述已经实现的代码；完整多游戏架构仍见 `architecture.md`。

## 运行边界

- 自写确定性贪吃蛇，初始蛇向右、长度 3，坐标原点在左上，x 向右、y 向下。食物由回合种子确定，每吃一个加 1 分。
- 四个方向始终全部提供，不用“安全动作过滤器”替模型做决定。反向输入保持当前方向是冻结的游戏规则，轨迹同时保存请求动作与实际方向。
- 每次请求之前游戏暂停，收到有效模型结果后推进一格；等待网络不消耗游戏步数。碰墙、碰身体、填满棋盘或步数耗尽结束。
- 每局深拷贝固定 Harness；每步检查请求编号、观测序号、动作集合哈希、模型名、思考状态及合法响应。Receipt 的绑定字段由本地适配器生成，不是服务端签名。
- 模型身份只验证服务返回的名称，没有验证模型权重文件摘要。同名模型被服务方替换时，需要人工重建实验基线。
- V1 不更新模型权重，不接 Jev，不读屏，不发送桌面按键；它用结构化棋盘状态验证局后进化底座。

## 组件

| 文件 | 作用 |
| --- | --- |
| `snake.py` | 固定规则、状态和计分；不选动作 |
| `providers.py` | StartLux typed decision 与 GLM chat/completions 适配，错误和输出校验 |
| `runtime.py` | 冻结一局、调用玩家、校验回执、机械执行、逐步记录 |
| `evolution.py` | 真实 `gepa.optimize` 的自定义 Adapter / proposer，训练反馈与文本候选 |
| `service.py` | 局后任务、串行调度、配对验收、版本发布、停止恢复 |
| `store.py` | SQLite 注册表、文件产物、原子发布与回合索引恢复 |
| `app.py` / `static/index.html` | 本地 HTTP API、实验台、棋盘与历史回放 |

局内运行器只持有 DecisionProvider；GLM 只存在于初始化和 GEPA 优化路径。没有“模型故障后由随机策略/路径规划器继续玩”的生产代码。

## GEPA 与验收

一次正式游玩结束后保存 `job-<episode_id>`。作业固定训练、选优、发布三组种子；本局种子属于训练，三组互不重叠，新增种子避开现有已记录回合。数据清单写入作业目录。

真实 GEPA 负责候选搜索和选优。本项目的 proposer 用 GLM-5.3 解释轨迹并返回两个文本字段；不让 GEPA 默认任务模型代替 Decision 玩游戏。每个候选的得分来自实际游戏。GEPA 内关闭“满分即跳过”，因为食物原分没有固定的 1.0 上界。

教练看到训练反馈和触发回合，包含前 2 步、后 8 步的有界样本及截断说明；完整轨迹保留在本地。选优回合只有成绩参与候选选择，其轨迹不发给教练；发布种子的轨迹和分数不输入本次反思。早期采样可能遗漏中局错误，后续应增加失败窗口和食物事件采样。

GEPA 选出不同候选才启动额外的配对发布验收；同一新种子上各玩一次，交替先后顺序。至少 4 对、平均收益 ≥ 0.5、每对不退步才发布。UI 可检查每对结果。无改进、格式错误或样本不足允许保留原版，不应伪造“每局变强”。

这是实验级经验门槛：还没有大样本置信区间、跨地图泛化、封存最终测试集或长期退化自动检测。历史发布证据可被人查看，长期反复查看也会降低其作为真正封存测试的意义。

## 持久化、失败和恢复

- 完整回合 JSON 原子写入，SQLite 保存索引；JSONL 在每步刷新，保存完整响应和前后状态。
- 正式回合保存后建优化任务；重启会为遗漏索引的完整回合 JSON 补索引，并为缺少任务的正式回合补任务。
- 进行中的 GEPA 作业重启后标为 `interrupted`，同配置再次运行先重试。每次创建新 attempt 目录，保留旧产物；不是从 GEPA 内部迭代的精确断点续跑，重试可能再次产生模型费用。
- 已保存为故障或用户停止的正式回合，在恢复时先用同种子重跑得到有效反馈；不能把中断分数当有效评测分数。
- 如进程在回合中途被强杀，仅有 JSONL、没有完整结束记录，该段保留用于审计，V1 不自动继续这个未完成回合。下一次从新回合开始。
- 晋级时在同一 SQLite 事务内更新活动版本指针与 `promoted` 证据；发布后的日志异常不会撤销批准记录。
- 回滚只允许同一棋盘/规则/步数预算/模型配置下，已初始化或已通过验收的版本。候选不能靠回滚按钮绕过验证。回滚后下一局生效。
- V1 一次只允许一个实验 worker；`./run.sh` 在 macOS/Linux 用文件锁拒绝重复启动。还没有多进程调度器或后台并行训练。

## HTTP 接口

只监听 127.0.0.1；跨站控制请求被拒绝，不向前端返回模型密钥。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/state` | 当前棋盘、实验状态、回合、版本与作业 |
| GET | `/api/health` | Decision 健康检查；GLM 可用性以最近真实调用为准 |
| POST | `/api/run` | JSON 运行配置；空对象使用当前设置 |
| POST | `/api/pause`、`/api/resume`、`/api/stop` | 控制当前实验 |
| GET | `/api/episodes/{episode_id}` | 完整回放轨迹 |
| POST | `/api/rollback` | `{"version_id":"h-…"}` 切换批准过的版本 |

默认配置：8×8、120 步、3 个训练场景、3 个选优场景、4 对发布场景、1 次反思、1 局正式游玩、正式局种子 42。连续游玩时正式局种子逐局加 1。

## 下一阶段

先扩大蛇的固定评测集并观察候选是否稳定改进，再把 `SnakeGame` 与规则/动作定义抽成正式 GameAdapter。之后接俄罗斯方块与马里奥；实时游戏需要额外实现时钟、动作持续时间、过期观测处理和延迟约束。现有 `contracts/` 是这些后续接口的提案，V1 不宣称已加载或执行那套完整 schema。
