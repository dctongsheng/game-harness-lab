# V4：完整反思反馈、按游戏初始化与真实 A/B 实验

日期：2026-10-17。实现版本 0.4.0；基于 [RSI 诊断](rsi-diagnosis-v1.md) 的第一阶段改进。

**结论：反馈与初始化接口已修复并实测；尚不能宣布稳定游戏能力提升。** 五子棋独立样本从 10/12 胜变成 12/12 胜，但增益区间含 0、未通过门槛；方块四个候选开发均分均为 0。全部三批实验（包含保留的首批负结果）共 **83 局、2,650 次真实 Decision 动作、12 次 GLM 反思，另有 2 次初始化**。每次动作都校验 `never`/无思考遥测并按规则重放，无脚本代打、无基础设施失败或重试；没有发布研究候选。

机器可读证据：[结果与审计摘要](experiments/feedback-v4-results.json)；可审阅的初始游戏资料、策略、研究候选和冻结试验种子：[研究 Harness 原文](experiments/feedback-v4-research-harnesses.json)。后者含未经批准、可能有事实错误的 LLM 输出，不属于 `harnesses/` 已批准包。

## 本次实现的范围

LLM 先依据游戏的固定规则、真实观察结构和动作语义，为当前 Decision 接口生成初始 Harness，再交给真实对局与 GEPA 反思检验。初始设计是待验证假设，不因它由 LLM 生成或满足 JSON 格式就认定有效。

`initialization_contract.py` 从已注册的真实适配器读取初始教学样本，提供六游戏各自的坐标、状态字段、动作粒度和计分边界。合同明确单步 choice、`think_mode=never`、完整候选集合、无跨步会话记忆、无搜索辅助。军棋教学样本只使用公共投影，不向教练提供种子、私子或私有合法动作目录。`CoachProvider.initialize` 仍返回游戏资料与两段策略，新增合同与模型来源记录；正式初始化版本会保存这份 provenance。

`feedback.py` 实现 `complete_events_v1`，成为局后优化默认格式：

- 去掉重复棋盘表示，将不变场景信息只保留一份，按完整事件提供前状态、动作和结果。
- 优先保留终局、可核实的一步漏胜/漏堵、首次状态复现或同方块往返，以及初始与关键变化。五子棋战术标签只用于局后教练证据，不进入玩家请求。
- 超预算省略完整事件，并给出精确的来源索引、遗漏范围和数量；不再对 JSON 字符串截首尾。
- 军棋保留候选当时合法可见的棋盘及战斗约束；结果仅从 `public_view` 取得，并接上对手行动的公共后果。未知身份不会因审计轨迹里存在另一方视角而变明。
- 连续相同动作只是中性事实，不等于循环；不同方块连续硬降不能标成“无效重复”。

旧 `legacy_excerpt_v1` 路径为对照实验保留。两种格式共用相同教练 system prompt、策略 schema、模型、GEPA 轮数和评测逻辑。修复后两臂还接收同一份 `immutable_runtime_contract`：复用初始化的能力与游戏语义，不读取会话、不含教学样本、种子或对局状态；合同内容与哈希写入反思记录。合同明确反馈投影不是玩家输入，五子棋压缩棋盘也统一为真实 `X/O/.`；方块明确每个动作末松键、下次同键形成新边沿，以及非空 hold 的交换语义。新反馈方案同时包含紧凑表示、完整记录、关键事件选择与诊断标签，因此本实验比较的是**反馈方案整体**，不能把任何差异只归因于取消字符串截断。

没有改变运行时观察、加入胜点计算辅助或最近动作历史；没有更改模型权重、合法目录、执行器、原生计分和固定对手。玩家每个实际动作依然由 Decision 返回选择，回执失败时停止，不以代码代选。

## 可复现实验设计

实际玩家 `startlux-decision-27b-autothink`、教练 `glm-5.3`。Decision 服务全局默认可能为 auto，但每次请求显式覆盖 `never`，并检查 `used=false` 和 reasoning tokens=0。原服务与实验数据目录隔离，不修改旧活动版本。

两个游戏各进行一次真实 GLM 初始化，并冻结同一父版供两臂使用：

| 游戏 | 共享初始 Harness | 初始 GLM 调用数 |
| --- | --- | ---: |
| 五子棋 | `h-6615906fd9707b25` | 1 |
| 俄罗斯方块 | `h-32b33bfd737f197d` | 1 |

两份原始输出、完整初始化请求和来源在 `data/experiments/feedback-v2-bootstrap/<game>/`。方块父版有一处真实生成的内部矛盾：brief 正确说明“动作结束自动松键、下次同键是新边沿”，strategy_notes 却声称“重复提交同键无效”。没有人工改写父版，也没有只给某一反馈臂修正。它是两臂共同面对的初始策略缺陷。

每游戏先运行父版触发局 1 场、开发局 4 场；这四场拆为训练 2 场、选择验证 2 场。五子棋每组包含候选黑、白各一次，均为标准空盘；方块为固定四个环境种子。两臂共享父版这四场回执与轨迹，避免分别重跑父版引入不相同的训练证据。

顺序在运行前固定为旧反馈第 1 提案、新反馈第 1 提案、新反馈第 2 提案、旧反馈第 2 提案。每个提案从同一父版独立启动真实 `gepa.optimize`，一轮反思。每个有效候选都完成相同四场开发试验；即使 GEPA 在训练阶段拒绝，仍补齐开发比较，但明确不把它称为 GEPA 入选版本。

因此每游戏开发阶段最多 21 场完整局：1 触发 + 4 父版 + 4 提案×4 候选局。格式无效提案不能冒充新候选。基础设施错误不记零分；如需恢复，只允许预先规定的有限重试，每个尝试独立落盘，已成功的教练响应与回合不会因恢复重新抽样。

开发选择条件在调用前写入不可改 manifest：平均原生分增益至少达到适配器阈值（五子棋 2、方块 100），每对不退步且至少一对提高。通过者中按平均增益选择一个；并列按预定顺序。开发集用于选优，不能作为独立效果证据。

只有有候选通过开发门槛，才开启一次独立最终测试：五子棋 12 对、共 24 场，每席位 6 对；方块 12 个新环境种子、每种子重复 2 次，共 24 对、48 场。新旧运行顺序交错，五子棋每席位内也平衡先后。最终要求原门槛、逐对不退步，以及预先固定方法的 95% 配对差区间下界大于 0。无候选通过开发阶段则保留最终集未使用，不为了得到正结果继续追加候选。

五子棋按席位分层，以配对运行作为分析单位，结果仅适用于标准开局与该冻结对手；方块先在环境种子内聚合两次重复，再按种子重采样。两臂各仅两个提案，A/B 汇总是描述性结果，不是充分估计反馈处理效应的统计实验。episode_id 仍随回合变化并进入玩家输入，且服务只报告模型名称，无法据此证明 checkpoint 字节相同。

## 命令与证据

初始化父版与准备实验分开，`prepare` 不调用模型，会冻结配置、代码哈希、对手、所有试验编号、顺序、门槛和预算；源码或配置改变后拒绝续跑旧实验。

```sh
.venv/bin/python scripts/initialize_experiment_harness.py \
  --game gomoku --output data/experiments/feedback-v2-bootstrap/gomoku
.venv/bin/python scripts/run_feedback_experiment.py prepare \
  --game gomoku --id feedback-v4b-gomoku-20261017 --seed 20261018 \
  --parent data/experiments/feedback-v2-bootstrap/gomoku/parent.json
.venv/bin/python scripts/run_feedback_experiment.py run-dev --id feedback-v4b-gomoku-20261017
# 仅开发门槛通过后：
.venv/bin/python scripts/run_feedback_experiment.py run-final --id feedback-v4b-gomoku-20261017
```

方块对应 `--game tetris` 和实验 ID `feedback-v4b-tetris-20261017`。实际已有目录不覆盖；重现实验应使用新目录与新 ID。`--retry-failed` 只用于已有失败尝试的受限恢复，不能用来重抽成功提案。

原始证据保存在 `data/experiments/<实验ID>/`：`manifest.json`、`parent.json`、逐局 `episodes/`、逐提案 `proposals/`、`calls.jsonl`、`development_result.json`，以及满足条件后生成的 `final_result.json`。每个完整回合立即按实际规则重放，核对完整动作目录、策略归属、原始模型选择、思考遥测和最终分数。实验 runner 不写正式 registry，不把研究候选直接当成已批准线上版本。

正式服务中的未来优化默认使用新反馈；通过既有发布门槛后仍按原来的 `harnesses/<game>/<version>/` 导出与 Git 同步路径工作。此次研究生成的初版、候选和原始回执仍保存在隔离的 `data/`，不混入已批准包。

第一批五子棋 `feedback-v4-gomoku-20261017` 完成 21 局、599 次真实 Decision 动作、4 次 GLM 反思。所有完整局均通过回执与规则重放审计，无重试或基础设施失败。

| Harness | 四场开发分数 | 均分 | 相对父版 |
| --- | --- | ---: | ---: |
| 共享父版 | 0 / 100 / 100 / 100 | 75 | — |
| 旧反馈 1 | 100 / 100 / 100 / 100 | 100 | +25 |
| 新反馈 1 | 0 / 0 / 0 / 0 | 0 | -75 |
| 新反馈 2 | 100 / 100 / 100 / 0 | 75 | 0 |

新反馈两个提案都把教练压缩棋盘的 `0=黑、1=白` 写成玩家 `observation.board` 的编码；实际玩家收到的是 `X=黑、O=白、.=空`。这能确认反馈接口语义缺陷，但没有足够对照将全部分差归因于它。新反馈也识别出了漏掉一步胜点等真实行为问题，不能简单总结为没有有效信息。

这批旧反馈 1 达到实验开发门槛，但四个提案均未被 GEPA 选为优于父版的验证最优项；实验的补齐开发评测与 GEPA 入选是不同判断。旧反馈 1 的 +25 全来自单个训练局翻胜，选择验证增益为 0，开发配对区间为 [0, 50]。在消费独立最终集之前发现接口问题，因此保留全部负结果和原源码快照，将本批标为 `superseded_before_holdout`。没有启动任何最终局。已准备但尚未调用模型的第一批方块目录同样停止使用。

修复后的批次使用新 manifest、新试验编号，沿用同一初始父版；没有修改首次输出以追求好成绩。

新反馈 1 已正确使用 `X/O/.`，但 GLM 把 `12→21→30→39→48` 称为 9×9 棋盘的“主对角线”；实际是 D2–D6 竖列。接口修复没有消除生成策略的事实错误。本轮保留原始输出，不人工修正或追加抽样。

新反馈 2 也把竖列 F3–F7 误称为斜线，但仍四局全胜；因此事实错误不能直接解释分数方向。旧反馈 2 多出空字段 `decision_instructions_note`，不是网络失败，按严格 schema 拒绝且不补抽。

### 五子棋独立最终对照：样本改善，未达到可靠性门槛

冻结开发选中的旧反馈 1 后，在未参与教练反思/选择的 12 对试验中，父版 **10 胜 2 负，均分 83.33**；候选 **12 胜 0 负，均分 100**。所有局均实际连五终局，没有把预算截断记作赢棋。两对从负变胜、十对持平，无退步对；均分增加 **16.67**。

按预注册、按席位分层的配对 bootstrap，95% 增益区间为 **[0, 33.33]**，下界没有大于 0，**最终门槛未通过**。黑方六对都持平，增益来自白方两对。样本中确实变好，但还不足以宣布稳定提升；不会因 12/12 胜而绕过门槛，也不追加最终试验直到“显著”。这是旧反馈候选的最终成绩，新反馈候选仅有开发证据。

本批开发与最终合计 **41 局、978 次 Decision 动作、4 次 GLM 反思**，无基础设施失败、无重试，未发布候选。

反向次数本身不是错误标签；同一 piece、锁定板和朝向不变时持续返回相同横向位置，才构成下文的摆动证据。更多操作、更多锁块或用满预算都没有带来任何消行。

**没有得分提升。** 无候选满足开发门槛，所以预留的 12 种子×2 重复最终集完全未使用，没有通过追加样本或改成“存活更久”来制造成功。

真实行为证据：

- 五个父版局（含触发局）共 60 次动作：51 次硬降、7 次顺旋、2 次 hold，**0 次横移**，11–16 步全部 TOP_OUT。两侧列仍有大量空位时持续堆高中央列；目录中左右移动动作实际存在。跨方块重复硬降是成功执行的新动作，不能当作循环或失效输入。
- 文字修改后出现横移，但未消行。新反馈 1 的 `exp-c5de200f86f44455366de11a`，piece 7、trace 34–54，在锁定板不变、T 朝向不变时，21 次动作让 x 在 3 与 7 间往返，直到自然锁块；该局 80 步预算结束仍为 0 分。旧反馈 1 也有同一块方块在 x=0 与 4 之间反复移动的实例。这里的循环证据限定同一 piece，避免混淆不同方块。
- 教练已能指出出生处堆塔、说明重复同键会产生新边沿，但还会生成错误策略。新反馈 1 把“列内占用格数”当成列高，且要求判断“本块是否已横移/旋转”，实际当前输入没有该历史；新反馈 2 把 `left/right:100` 简化成移动一格。真实回执 `exp-13891f4a36fc3560d6bb7f23` trace 32 的 `left:100` 是 x=3→1，计时器状态会影响实际位移。规则没有在本轮改变。

这些能确认策略事实错误、目标保持和动作尺度问题存在，**不能用观察性轨迹单独证明哪个因素造成全部 0 分**。

## 本轮验证到了什么、下一步如何验证

1. **工程修复有效**：默认新反思不再接收首尾截断的半条 JSON，真实调用中两臂共享同一运行时合同；首批五子棋字段编码错配未在第二批合法提案中复现。初始化已经是“按游戏与模型接口设计初版，再逐局评测和迭代”。
2. **初版和反思都需要验证**：GLM 知道接口限制仍可能写错棋形、时间粒度或依赖不存在的历史。严格 JSON schema 仅验证结构，不等于游戏语义正确。不能因为生成了新 Harness 就把它视为改进。
3. **这轮没有证明新反馈优于旧反馈**：两臂各两提案、开发集很小；新反馈五子棋有一个开发入选候选，但最终测试按既定规则选中了旧反馈候选。方块两臂均为 0。五子棋测试父版从开发 50 到最终 83.33，也说明短批次波动与上限效应不可忽略。
4. **下一阶段应改变玩家得到的信息，再做单因素对照**：保留全部原生动作与 `think_mode=never`，增加可从当前棋盘核实的结构事实（如列顶高度、洞、棋形坐标），不排序、不筛除动作；另做一组由 Decision 自己选择并持久化目标的实验（当前 piece、目标列/朝向、失效条件），每次游戏按键仍交给 Decision，避免 LLM 参与局内代打。先分别测“仅结构事实”和“仅目标记忆”，不要同时改模型、反馈和评分。
5. **验证方法**：从本轮失败轨迹冻结局面，先检查相同输入下能否稳定避免一步漏胜、错误位移和同块往返；然后用未消费的新种子与冻结父版做成局配对对照，报告原生分、失败率、成本和不确定性。局面题做对不能替代成局得分。若结构与目标保持仍无改善，才在相同接口/观察/思考设置下比较其他获授权的 Decision/Jev 模型，将模型因素与 Harness 因素分开。

本轮只完成并部署第一阶段，不把以上后续实验当作已经实现或已经有效。正式游戏的既有发布门槛保持不变；研究 runner 另加区间门槛，不会把其候选自动写入正式 registry。
