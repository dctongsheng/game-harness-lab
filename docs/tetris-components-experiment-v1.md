# 俄罗斯方块：可进化组件与改进经验库真实对照 V1

正式实验 ID：`components-tetris-v2-20261019`。实施说明见[可进化组件与改进经验库](evolvable-components-v1.md)。

**结论：组件与经验库闭环已实现并通过真实运行审计，本轮没有选出提升版本。** 三组正式平均分均为 662.5；最终都保留共同父策略，独立验收全部为 `retained`。这份报告同时保留未成功的提案和分析限制。

## 研究问题与固定边界

本轮检验两个问题：允许优化目标规划、有限记忆和观察组织，是否比只允许优化策略文字更好；加入有真实训练证据的历史经验，是否进一步改善选出的版本。

三组共享同一个 V8 衍生的五组件初版、同一 Decision 模型、图片输入、原生规则与每局 80 次动作预算。V8 迁移新增了统一的记忆指导和观察顺序，因此历史 V8 的成绩不作为本轮基线。

| 条件 | 可修改内容 | 额外经验 |
| --- | --- | --- |
| A：text | 决策指令、策略说明；其他三项固定 | 无 |
| B：components | 上述两项＋目标规划、记忆策略、观察组织 | 无 |
| C：experience | 全部五项 | 独立 bootstrap 训练配对形成的冻结快照 |

A 组也使用五组件执行器；它与网页中的原始两字段模式不同。这一设计把初版能力和观察信息保持一致，比较的是优化范围。不同组的实际对局不会因候选文字相同而复用成绩。

局内目标和所有原生按键均由 `startlux-decision-27b-autothink` 选择，请求显式使用 `think_mode=never`，且核验返回的思考使用标志和 token 数。LLM 教练为 `glm-5.3`，只在离线反思和经验提炼中使用。40 个条件落点后果保留完整，程序不排名、不筛选，不自动执行到目标的按键路径。

## 预登记流程

1. 先在独立的 2 个训练、2 个选优种子上做一次 bootstrap 搜索。经验只提取实际训练配对，不读取选优或验收轨迹；无可靠经验时允许 `NO_ENTRY`。
2. A/B/C 使用另一组共同的 2 个训练、2 个选优种子，各运行一次 GEPA、一次反思。三组的共同触发局仅用于给教练相同起点，GEPA 的评测回调都实际运行游戏。
3. 冻结全部候选与经验快照，使用 8 个未参与开发的种子完成 24 局正式比较。预先规定主要差值为 B−A 和 C−B。
4. 使用另外 4 个种子完成共同父版与三组的 16 局发布验收。三组分别验收，不根据正式比较挑出一组后重用同一测试集。
5. 发布要求：策略确有改变，至少 4 对，平均原生积分增加至少 100，且每一对都不退步。通过也只隔离导出，不自动激活生产版本。

得分只使用原生消行积分。软硬降、存活和目标选择不额外加分。目标调用不占原生动作预算，但单独计入推理成本。正式组间差值按配对种子 bootstrap 10,000 次报告探索性 95% 区间，不做经多重比较校正的显著性宣称。

## 验证与可复查边界

实现回归：1,087 项测试和 9 项子测试通过。完整测试排除了原有、未完成的王者荣耀集成文件；其改动没有纳入本次提交。另在临时本地服务中检查了俄罗斯方块的三模式选择与显示。

每个有效对局都重放原生动作，核对每步棋盘、最终得分、目标记忆和实际输入顺序。图片由保存的状态重绘核验，并与 HTTP 内容、原始返回及 Decision 回执绑定。基础设施失败不记为零分；显式重试保留失败记录，不重试已成功的逻辑对局。

正式实验的预登记清单保存 Python、CJS、TypeScript、JSON 与 vendor 许可文件的哈希和代码快照，同时固定 Node、GEPA、Pillow、httpx 版本、模型配置和种子分区。在任何真实调用之前核对游戏规则与原生引擎上下文；每局完成后再做原生重放核验。模型身份依据服务返回名称，无法独立证明同名服务背后的权重从未替换。

最终离线审计状态为 `completed`：68 局全部重放，7,404 次动作／目标调用均绑定原始请求与回执，2,052 张去重图片核验通过；Decision 请求均使用 `never` 并通过零思考回执检查。没有不完整尝试，训练经验来源检查通过，87 个冻结源码文件未改变。见[审计与证据摘要](experiments/tetris-components-v1/evidence.json)。

## 预试验中发现并修复的问题

第一份预登记 `components-tetris-v1-20261019` 已退役，不纳入正式效果统计。它完成了 7 局 bootstrap 相关对局和一次未完成的共同触发局，尚未运行 A/B/C 搜索、正式比较或发布验收。

在经验提炼时，原先每局 3,000 字符的反馈预算被棋盘上下文占满，`trace_sample` 为空。教练只读到修改与分数，生成了缺少行为证据的泛泛建议。用同一份已归档对局复查，预算提高到 12,000 字符后保留了 4 个动作片段。修复同时规定：任何父版／候选反馈没有完整动作片段时，返回无经验，不再调用教练强行提炼。

旧数据、源代码快照及审计完整保留。旧审计重放了 7 局、765 次有效局内调用；归档有 855 次请求、854 次回执，其中 89 次属于未完成的触发局，最后 1 次在停止时未完成。旧阶段另有 2 次 LLM 调用。这些消耗单列，不并入新对照的效果统计。重新登记采用全新种子；修复原因是反馈内容缺失，未利用正式测试结果挑选版本。

另做了一次独立真实初始化检查：`glm-5.3` 按新合同成功生成五个组件，参数校验通过。这是一次逻辑初始化，实际发生两次教练调用，第二次响应通过结构校验；两次分别报告 8,946 和 11,484 tokens。该初版未获批、未进入对照或经验库，成本单列为集成验证，见[初始化检查摘要](experiments/tetris-components-v1/initialization-smoke-summary.json)。

三组最终都保留了共同父策略，候选内容哈希完全相同：`f3053753c2c073f68bb51d2997cbe0c4d1b6a27375634ee38cc1da8c6a325caf`。各组的提案训练配对为：

| 组 | 配对 1：父版→提案 | 配对 2：父版→提案 | 平均差值 | 最终选中 |
| --- | --- | --- | --- | --- |
| A：text | 300→300 | 700→600 | −50 | 父策略 |
| B：components | 300→400 | 1,000→700 | −100 | 父策略 |

三个提案都未进入 GEPA 的候选池，均未执行提案的选优集对局；每组实际完成 6 次评测回调。C 确实读取了 1 条冻结经验，因此不是经验缺失导致处理未发生。

A 的提案修改两段文字，B/C 的提案修改了全部五个字段里的指导文字。但 B/C 都保留了 `recent_actions=4`、`replan_every_actions=4` 和共同父版的观察区段顺序。这次实际搜索没有探索不同的记忆长度、目标调用频率或观察排列，因此不能用本轮结果判断这些结构参数改变的效果。

**本轮搜索未选出改进版本。** 正式阶段的 A/B/C 实质上是同一策略的重复测量，不能把它称为三种不同新 Harness 的能力比较。不能用这个结果推断可进化组件或经验检索在更充分搜索下必然无效。独立验收还要求策略确有改变，三个未变化的版本均未获批发布。

### 当前父策略还存在什么问题

以下为每组 8 局的相同行为统计，不能视为三份独立策略带来的改善：

| 行为指标 | 实测 |
| --- | ---: |
| 锁定方块 | 180 块 |
| 每锁一块使用的原生动作 | 3.56 次 |
| 到达目标列及朝向后，下一动作立即硬降 | 180/180 |
| 同方块、棋盘、朝向和目标下的可比较横移反向 | 30/105，28.6% |
| 横移从目标列一侧跨到另一侧的严格过冲 | 30/292，10.27% |
| 目标调用 | 224 次：185 次在无旧目标时设定，30 次重复原目标，9 次保留原目标 |

具体例子：`evaluation-00` 的第 13 个动作（原始 `before.step=12`）为 `right:100`，方块占用的最左列从 6 移至 8，越过目标列 7；第 14 个动作反向短按回到列 7，第 15 个动作硬降。第 41 个动作也有长按越过目标后反向修正。这说明“到位后继续乱走”在这批样本中没有出现，按键时序与过冲仍有可研究的效率损失。

另有 168 次顺时针旋转、0 次逆时针，其中 5 段连续三次顺时针完成 `0→1→2→3`。不能据此直接宣称逆时针替代必定可达或增分；必须用同一原生旋转与碰撞规则验证。上述行为诊断仅用于分析后续问题，不回填这轮经验库或修改被冻结的策略。

## 冻结经验的质量核查

正式实验生成了一条训练证据支持的条件性经验：两对原生得分为 700→700、1,000→1,600，平均差值 +300。决策指令、策略说明和记忆说明同时改变，条目明确标记 `confounded=true`。该结果仅描述这两对训练样本，不是正式效果结论。

提炼请求中的四份父版／候选反馈各保留 4 个真实动作片段，每份约 10,300 字符，含完整的 22 行前后棋盘；动作、分数、种子与策略哈希均对上原始存档。快照只来自 bootstrap 训练局，未包含选优、正式比较或发布验收数据。

数值绑定可靠，不代表 LLM 的解释自动正确。冻结经验里有三处需要限定，原文保留以忠实记录 C 组实际看到的内容：

- “开局序列相同但续块序列不同”的说法混淆了队列消费进度。两对初始观察与种子完全相同，且均未暂存换块；按相同 `pieceId` 对齐，已有的方块类型与后续队列逐项相同。候选在 80 步内分别多锁定了 1 块、3 块，结束时看到不同队列不意味着环境序列不一致。
- “反向后短按可靠移动一格”应理解为相应按键时序下的一次横移尝试；墙或锁定方块仍可能阻挡移动。
- “每块 6–8 个动作、微调 3–4 次”等数值是候选建议，没有单独做阈值消融，不能说这些具体数字分别经过验证。

因此，经验文字是带证据引用的待验证建议；可验证事实、数值变化和因果解释需要分开看。

另对 B 组反思候选的实际输入做了语义核查：观察指导要求读取 `observation.remaining_steps`，但真实字段位于顶层 `remaining_steps`；`grounded`、`lockTicks` 确实在 `observation` 内。它使用的 `control_facts` 是不准确的简称，实际名称为 `tetris_control_facts`；`recent_actions` 则确实存在于 `decision_goal_memory` 中。结构校验能保证组件格式、范围和执行边界，不能保证自由文字里的字段路径都正确。此处保留冻结提案原文，并记录错误；没有据此推断它造成了多少分数变化。

## 解释限制

- 每个条件只有一次优化、正式比较只有 8 个种子；结论针对这次选中的版本，不能估计优化算法跨多次运行的平均收益。
- 开发阶段各搜索作业有不同的局 ID，且该 ID 出现在玩家输入的 `episode_id` 和记忆作用域中；训练配对的父版与提案也使用不同身份。A/B 同一父版、同一种子的重复基准在两局出现分差；首个动作分歧之前，指令、动作目录、图片和其他状态相同，只有上述身份字符串不同。因此不能称为“完全相同输入下的随机差异”，训练分差也不能单独归因于策略修改，更不能用单次开发过程证明哪种优化算法更强。正式比较与发布验收按种子共享输入身份，以减少这项干扰。
- 本轮有固定 80 次原生动作的预算，不代表长期高分或游戏通关。
- 五组件组可以同时改多个组件，不能把总体差值归因于其中单项；经验条目也明确标注这种限制。
- 经验组使用额外 bootstrap 计算，必须单列这些对局和教练成本。
- 通用服务目前是结构化文字输入；本轮研究所有组都附带视觉，结果不能直接套用到网页默认输入模式。
- 通用接口已可扩展，但完整五组件运行合同目前只在俄罗斯方块接入。

## 下一轮可检验的改进方向

这些是本轮结果导出的建议，尚未作为本轮新代码或已验证收益交付：

1. **先消除开发输入的身份干扰。** 将执行 ID 留在审计元数据中，或让同一种子的父版／候选在玩家输入中使用相同身份；再检查父版重复运行是否一致。正式比较已采用共享身份，下一轮应扩展到训练配对。
2. **让修改更小、检查更具体。** 优先一次只改一个组件，附上上述过冲与重复规划片段；明确允许引用的真实字段路径，拒绝不存在的字段说明。先比较记忆频率 `2/4/8` 或观察顺序，避免“允许改结构、实际只改长篇文字”。
3. **给搜索覆盖设置预算。** 本轮每组只有一个提案；下一轮应预登记多提案的相同总预算，并同时报告得分、消行和调用成本。继续保留未见种子验收，不因某次训练高分直接发布。
4. **把经验事实与解释分开。** 队列应按 `pieceId` 对齐，按键效果应记录阻挡条件；未验证的阈值保持为假设。已有证据支持“多锁了几块”，不自动支持“续块序列不同”或某个阈值最优。

模型是否构成主要瓶颈仍需额外对照。本轮直接暴露的是候选质量、结构搜索覆盖及开发配对输入一致性的问题；没有证据把未提升全部归因于 Decision 模型。
