# 俄罗斯方块：优化前后实时对照页

启动：`.venv/bin/python -m game_harness.tetris_comparison --port 18769`。

打开 <http://127.0.0.1:18769/>，点击「开始同种子对照」。页面同时显示两块真实棋盘、原生积分、消行数、动作数、最近按键，以及优化后减优化前的分差。支持同时暂停、继续、停止、换种子重开。默认每方 80 次动作，可设 8–1000；每次默认随机选新种子，不预选有利局面。

## 两边的共同条件与差异

两边使用同一配置的 StartLux Decision、`think_mode=never`，每次目标和动作选择均附当前原生棋盘图片。相同环境种子、7-bag 方块序列、规则、原生动作目录、按键策略、模型可见 episode ID 与动作预算；每个目标、按键和按住时长均来自模型回执。

左边是上一轮正式实验的原始 baseline Harness：V2 结构化棋盘、目标记忆、控制反馈与旧目标提示。右边是同轮 planning Harness：V3 独立 GLM 目标提示，加完整 40 项条件落点后果。基线从该批冻结 manifest 原样导出至 [baseline-harness.json](experiments/tetris-landing-v8/baseline-harness.json)；优化版复用 [research-harness.json](experiments/tetris-landing-v8/research-harness.json)。启动时校验两份资料仅在版本 ID 与已声明的上下文配置上存在差异。

两个独立游戏线程在原生动作结束后协调进度，两边都活跃时最多领先一个动作。一边正常结束后，另一边继续至自己的终局或相同预算。同步的是动作步数，不是物理 tick 或方块数量；模型选择的按键时长和 hold 行为可以不同。屏障不会选择动作或改变物理游戏时钟。

## 结果口径与证据

正在进行时显示当前差值，不下最终结论；只有两边正常完成才比较最终积分，允许优化前更高或平分。用户停止、模型错误与记录失败都会明确标记，本组不能用于判断提升。等待模型期间暂停物理时钟；页面每个原生动作刷新画面，显示的决策耗时取回执，不把同步等待计成模型延迟。

体验记录独立写入 `data/experiences/tetris-comparison-v8/pairs/<pair-id>/`：

- `manifest.json`：相同种子、模型、预算、两份冻结 Harness 及哈希。
- `baseline/`、`planning/`：各自 `trace.jsonl`、`result.json`、请求/回执 `calls/` 和原始图片 `images/`。
- `summary.json`：本组完成状态、双方原生成绩与结束原因。

图片目录独立，避免两个线程同时创建同哈希文件产生竞争。相同 episode ID 只用于模型输入，各组证据文件分别保存；新对照使用新 ID，不覆盖旧记录。页面仅绑定本机，拒绝跨站控制请求。体验不运行 GEPA、不写生产活动版本，也不修改正式对照证据。

单组实时体验不保证提升，也不能代替多种子的统计结果。上一轮 12 对正式结果见 [V8 验证报告](tetris-landing-validation-v8.md)。

## 页面验证

2026-10-18 已通过浏览器点击开始、暂停和继续，真实请求检查确认两侧初始观察与 PNG 一致、episode ID 与预算相同、图片哈希可还原、思考关闭。暂停期间两侧原生步数保持不变，恢复后继续更新。首组使用页面随机种子 2088717070，属于功能体验，不加入之前的 12 对正式统计。

新增 15 项测试使用原生规则引擎和受控模型回执，覆盖公平输入、按步屏障、一侧堆顶后另一侧继续、暂停与停止的在途动作、构造/调用/收尾异常释放、历史不覆盖及本地访问边界；不将测试回执当作模型能力证据。与 62 项原有网页/框架/服务测试合计 77 项通过。
