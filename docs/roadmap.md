# 实施顺序与验收

本文件是后续开发计划，不是已实现功能列表。首版环境选择“可暂停”已由用户确认。

## 阶段 0：固定规则与模型接口

先完成 `GameSpec`、动作语义、观测权限、得分函数与 `DecisionProvider`。StartLux 是首选适配，Jev 作为可替换 provider；同一回合不静默切换。

验收：

- 通过真实 API 返回的 model 字段核对服务自报名称；StartLux 还记录实际加载的 checkpoint、权重哈希和配置，托管 Jev 尽可能固定不可变 revision。若只能获得可漂移别名，标记版本不可验证，限制跨时间成绩的可比性。每个后端至少完成一组真实 Choice 请求，不用 mock 充当集成成功。
- 返回不存在的 ID、概率 NaN、错误候选集、过期回答、超时后，均没有未授权动作执行。
- 对某后端不保证的概率字段，不伪造数值；按 provider 明示能力验证并统一回执。
- 模型版本、环境版本、规则和原始得分的日志能完整回溯。
- 已有服务只做健康检查再决定如何使用，不先重启。接口地址与凭据从运行配置注入，仓库只放占位符。

## 阶段 1：贪吃蛇，跑通最小闭环

蛇是首选，因为动作空间小、错误容易定位、暂停步进自然。依据游戏环境研究选择有许可证的现成实现，或写最小规则明确的引擎；先固定一种，不把多个规则变体混评。

交付：结构化状态适配、每格 Choice、事件日志、LLM 初始化、GEPA 自定义 Adapter、串行局后优化、选版与回滚。

可演示的用户路径：

```text
新建蛇实验
 → 自动生成游戏资料及 H0
 → StartLux 独立完成第 1 局，展示原分与回放
 → GEPA 根据失败事件生成 H1/H2
 → 同场景与 H0 比较，展示通过或拒绝原因
 → 第 2 局使用被批准的版本
```

验收分开看：

1. **工程闭环：** 连续 10 个正式回合均产生唯一优化任务，有候选尝试及明确结论；优化评测没有递归派生任务；重启不重复发布。
2. **控制约束：** 实际日志中无局内教练调用、无脚本代选动作；危险但可执行动作未被候选筛选层隐藏。
3. **改进证据：** 冻结后在封存场景比较 H0 与选中版，公布全部成绩及区间；未提升也如实输出，不将“完成十轮”叫作能力提升。

基线至少包含同一个决策模型的固定 H0；随机动作只能作独立环境诊断基线，不能接入正式玩家兜底。模型之间的比较另做实验，不能把换模型和改 Harness 的效果混在一起。

## 阶段 2：俄罗斯方块，验证跨游戏复用

复用运行器、模型适配、GEPA、审计和发布模块，仅添加 GameAdapter 与 GameSpec。冻结旋转、计分、生成分布、hold/hard-drop 可用性。

首版 primitive 模式由模型选择左、右、旋转、下落、落下等实际开放动作；重力与按键频率均写入规则。后期可以另设 placement 模式，由模型从可达落点选择，执行器仅实现已选动作；两种模式分别报告。

验收：固定种子可回放；报告原分、消行、堆叠失败；候选集不靠启发式权重自动选最好落点；候选之间使用相同动作抽象与时钟；GEPA 不修改计分逻辑。

## 阶段 3：超级马里奥，验证时序控制

优先使用可步进的模拟器。具体游戏版本与合法游戏资源是接入前提；首期不下载或分发商业 ROM。现成 Python 包的具体依赖以固定版本验证，不照搬旧教程兼容性结论。

模型选择“按键组合 + 短固定帧数”，实际执行时不根据敌人位置自动修改。先观察结构化/引擎信息的研究轨道，再单开画面观察轨道；两种信息条件严格区分。

验收：至少 3 种场景家族，包括平台跳跃、敌人交互、坑洞；训练与测试按关卡/布局家族分离，不仅换同一关卡种子；原分、推进距离、通关率和死亡类型单列。新场景测试不能只重复背诵 1-1。

## 阶段 4：真实时间与后台优化

先在上述游戏逐步加速、引入延迟抖动和推理负载，找出动作过期率、P95/P99 和游戏时间预算之间的关系。只有在目标输入频率下实测通过，才启用不可暂停模式。

增加工作队列、单发布者、旧候选重验、资源优先级、固定版本回合、动作幂等和故障注入。确认运行中优化任务不会挤占玩家的推理时限。

## 阶段 5：多角色与王者荣耀

先通过公开可用环境检查游戏状态和动作接口，再依次做单英雄、少量角色、完整队伍。具体 Gamecore、模式和授权条件先核实；开放训练 SDK 不等于商业客户端可直接自动操作。

局内团队目标与各英雄动作都由决策模型选择；LLM 只赛后生成战术说明和组织方式。引入英雄视野、部分可观测状态、动作并发和协调超时。环境自带的寻路/自动攻击行为必须列入动作语义，不能隐去其对成绩的贡献。

验收包括合法观测、防隐藏信息泄漏、固定对手集、未见英雄/阵容测试、真实实时预算、完整动作归属。模拟器机器人胜率与真人对局成绩分开，不外推。

## 建议的开发目录（尚未创建实现）

```text
src/game_harness/
  contracts/       # 对象、版本、字段与事件
  games/           # 每种游戏的观测、动作、时钟、计分
  providers/       # StartLux / Jev transport
  runtime/         # 编译、记忆、决策、验证、执行
  knowledge/       # 来源、规则、攻略和摘要
  evolution/       # GEPA Adapter、反思样本、预算、恢复
  evaluation/      # 配对比较、分割与封存报告
  registry/        # 制品、哈希、选版与回滚
  observability/   # 回合回放、调用链、得分与成本
```

不预先规定“每轮必涨多少分”或“30 分钟一轮”。先量出单次决策、完整回合及候选评测成本，再确定每局能承受的候选数和评测数量。
