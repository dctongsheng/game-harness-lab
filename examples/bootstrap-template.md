# LLM 初始化输出模板

本文件是后续教练提示词的设计模板，没有实际调用 LLM。占位字段需由可信 GameSpec 与资料提供，不能让 LLM 自行猜测后当作事实。

## 输入

```text
你负责首局前设计 Harness；游戏开始后你不会参与动作选择。
唯一玩家是固定的 StartLux Decision 或 Jev。

GameSpec：{{trusted_game_spec}}
批准的观测字段和事实算子：{{observation_and_feature_allowlist}}
固定动作目录：{{trusted_action_catalog}}
来源材料及版本：{{source_documents}}
Harness JSON Schema：{{harness_schema}}
模型上下文和延迟预算：{{measured_provider_capabilities}}

请输出下述 GameBrief 和一个符合 schema 的 HarnessBundle。
没有来源支持的策略标记为 hypothesis；不能更改规则、评分、动作目录或测试场景。
不要输出可执行策略程序、网络请求、自动选动作表达式或默认兜底动作。
```

## GameBrief 输出

| 字段 | 应填写内容 |
| --- | --- |
| 游戏身份 | 名称、版本、模式、环境提交与规则版本 |
| 背景 | 简要说明游戏世界和玩家角色，只保留决策相关内容 |
| 目标 | 原始分数、任务成功条件、固定预算，三者分开 |
| 硬规则 | 已核实的移动、碰撞、旋转、重力、终止等机制 |
| 可用信息 | 本轨道允许的状态及信息缺失，不假设全图可见 |
| 可用动作 | 解释固定目录，不新增自动战术或工具 |
| 常见失败 | 失败类型和需要观察的证据，不预先强制选某动作 |
| 攻略卡片 | 来源、版本、建议、适用条件、置信范围/未验证假设 |
| 记忆需求 | 历史窗口和可选阶段，阶段选择必须由决策模型完成 |
| 初始策略 | 简单、可评估的起点，避免堆满所有攻略 |
| 未知事项 | 缺失事实和需在环境中验证的问题 |

GameBrief 是可审计资料；实际请求只取与当前状态相关的有界部分。成熟游戏攻略按游戏/版本索引，不能把整个网页或隐藏关卡答案每步塞给模型。

## 局后反思输入

```text
当前版本与候选允许修改的组件
触发本任务的回合：原分、结束原因、全部指标和关键失败窗口
过去训练样本：包括有效经验与回归案例
每个关键时刻：观测、完整候选、模型选择、实际动作及结果
基础设施事件：延迟、无效输出、断连，与游戏失误分开
上轮修改及评测结果：哪些解释已经被证据否定
```

必须要求反思输出“证据 → 可检验假设 → 最小组件修改 → 预期改善与可能回归”。生成新版本不代表发布成功；发布由独立评测器决定。完整日志留存，发给模型的摘要应标注抽样/省略范围。
